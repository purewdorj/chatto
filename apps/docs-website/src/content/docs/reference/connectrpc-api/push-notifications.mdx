## PushNotificationService

Push notification device commands for the authenticated user. Browsers
register Web Push subscriptions. Native mobile apps register APNs or FCM
device tokens.

<a id="chatto-api-v1-PushNotificationService-Subscribe"></a>

### Subscribe

Stores or updates the caller's browser push subscription.

The server must have Web Push configured. Clients normally call this after
the browser grants notification permission and returns a PushSubscription.
A stored subscription expires 180 days after its most recent save. The
client owns the refresh: call Subscribe again when the app starts and at
least once a day while it runs, and when the browser replaces the
PushSubscription. The server removes expired records itself. Call
Unsubscribe to stop delivery before the subscription expires.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/Subscribe
```

<a id="chatto-api-v1-SubscribeRequest"></a>

#### Input: SubscribeRequest

Request to store a PushSubscription returned by the browser Push API.

| Field | Type | Description |
| --- | --- | --- |
| `endpoint` | `string` | Absolute HTTPS push service endpoint URL. The server rejects redirects and destinations that resolve to private or other special-use addresses. |
| `p256dh` | `string` | Client P-256 ECDH public key from PushSubscription.keys.p256dh. |
| `auth` | `string` | Authentication secret from PushSubscription.keys.auth. |
| `user_agent` | `optional string` | Optional browser user-agent string for device identification. |
| `client_host` | `string` | URL host of the Chatto server that supplied the installed web app. The sending server combines this with its own hostname to reconstruct the client route. A host can include a port but no scheme, path, or user info. |
| `cleanup_token` | `string` | Random per-save capability generated by the client. A cancelled save can later remove only the record carrying this exact token, even when the same browser PushSubscription has since moved to another account. |

### SendTestNotification

Sends a test notification to the caller's registered browser
subscriptions and native devices. Calls are rate-limited per account.
The call succeeds when at least one device accepts the notification.
Delivery failures return a generic unavailable error without exposing the
push provider's response body.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/SendTestNotification
```

<a id="chatto-api-v1-PushNotificationService-RegisterNativeDevice"></a>

### RegisterNativeDevice

Stores or updates the caller's native mobile push device.

The server must deliver to the requested platform. Read
ServerRuntimeConfig.native_push_platforms to find the platforms that the
server supports; the call fails with FAILED_PRECONDITION for other
platforms. The app_id must be an app identifier that the server operator
allows; the call fails with INVALID_ARGUMENT for other identifiers.

A stored device expires 180 days after its most recent save. The client
owns the refresh: call RegisterNativeDevice again when the app starts, at
least once a day while it runs, and when the operating system issues a
new token. The server removes expired devices itself, and it removes a
device when the push service reports that the token is no longer valid.
A device token is active for only the account that most recently
registered it. Call UnregisterNativeDevice to stop delivery before the
device expires.

Native push sends notification content to Apple or Google in clear text.
The server operator can configure the server to omit message previews.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/RegisterNativeDevice
```

<a id="chatto-api-v1-RegisterNativeDeviceRequest"></a>

#### Input: RegisterNativeDeviceRequest

Request to store a native mobile push device.

| Field | Type | Description |
| --- | --- | --- |
| `platform` | [`NativePushPlatform`](/reference/connectrpc-api/types/#chatto-api-v1-NativePushPlatform) | Push service that delivers to the device. |
| `token` | `string` | Device token from the operating system: the APNs device token or the PushKit VoIP token as hex, or the FCM registration token. |
| `app_id` | `string` | App identifier: the iOS bundle ID for APNs and APNs VoIP, or the Android package name for FCM. |
| `apns_sandbox` | `bool` | True when the APNs token belongs to the APNs development (sandbox) environment, for example a debug build. It applies to APNs and APNs VoIP tokens. The server ignores it for FCM. |
| `device_name` | `optional string` | Optional device name for device identification. |
| `cleanup_token` | `string` | Random per-save capability generated by the client. A cancelled save can later remove only the device record carrying this exact token, through chatto.auth.v1.PushSubscriptionCleanupService.DeleteNativeDevice. |

<a id="chatto-api-v1-PushNotificationService-UnregisterNativeDevice"></a>

### UnregisterNativeDevice

Removes the caller's native push device by device token.

The call is idempotent: removing an unknown token still succeeds. The call
succeeds also when the server no longer delivers native push.

```http
POST /api/connect/chatto.api.v1.PushNotificationService/UnregisterNativeDevice
```
